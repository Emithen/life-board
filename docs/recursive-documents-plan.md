# 재귀적 포함 문서 도메인 기획

## 배경과 목표

현재는 `topics` 아래에 `documents`가 한 단계로 놓인다. 주제는 문서가 아니어서 본문을 쓰거나 하위 주제를 만들 수 없고, 문서는 다른 문서를 포함할 수 없다. 이를 **모든 지식 항목이 문서인 구조**로 바꾼다. 문서는 제목과 본문을 가지며, 다른 문서 안에 들어갈 수 있다. 포함은 여러 단계로 이어질 수 있다.

예: `개발 공부 → 데이터베이스 → PostgreSQL → 인덱스`. 각 단계는 열어서 읽고 편집할 수 있는 문서다. Todo는 이번 변경에서 분리된 기능으로 유지한다.

## 용어와 기본 결정

- **루트 문서**: 상위 문서가 없는 문서. 현재의 주제 카드 역할을 한다.
- **하위 문서**: 다른 문서에 직접 포함된 문서. 자신도 하위 문서를 가질 수 있다.
- **포함 관계**: 탐색·정리 목적의 부모와 자식 관계다. 본문에 다른 문서의 내용을 복제하거나 자동으로 합쳐 보여주는 기능은 아니다.
- **포함은 단일 부모**: 문서의 직접 상위 문서는 최대 하나다. 따라서 전체 포함 구조는 여러 루트가 있는 트리다.
- **참조는 다대다**: 문서는 다른 문서를 여러 개 참조할 수 있고, 한 문서는 여러 문서에서 참조될 수 있다. 참조는 포함 위치나 소유권을 바꾸지 않는다. 역참조는 자신을 가리키는 참조의 반대 방향 조회다.
- 깊이 제한은 데이터 모델에 두지 않는다. 화면은 깊은 구조에서도 현재 문서의 경로와 상위 문서로 돌아가는 길을 보여줘야 한다.

## 사용 흐름

1. 첫 화면에서 루트 문서를 만들고, 루트별 하위 문서 수와 최근 활동을 본다.
2. 문서를 열면 제목·본문, 상위 문서로 돌아가는 경로, 직접 하위 문서 목록을 본다.
3. 현재 문서 안에서 새 하위 문서를 만든다. 생성 직후 새 문서를 열어 내용을 작성할 수 있다.
4. 문서를 다른 문서 밑이나 루트로 옮길 수 있다. 자기 자신 또는 자신의 하위 문서 밑으로 옮기려 하면 이유를 알려주고 막는다.
5. 문서를 보관하거나 복원한다. 보관은 하위 문서의 원본 상태를 바꾸지 않는다.
6. 문서 상세에서 다른 문서를 검색해 참조로 추가하거나 제거한다. 같은 화면에 `참조하는 문서`와 `이 문서를 참조하는 문서`를 구분해 보여준다. 여러 문서가 같은 대상을 참조할 수 있다.

초기 화면은 직접 하위 문서만 보여주고, 각 항목의 하위 구조로 차례로 들어간다. 전체 트리 탐색은 후속 단계로 둔다. 참조 대상을 찾기 위한 제목 검색은 제공한다. 본문은 현재의 짧은 Markdown 텍스트 입력을 유지하며, 이번 단계의 참조는 본문 안의 특수 문법이 아닌 별도 관계로 관리한다.

## 데이터 규칙

`documents`를 유일한 지식 항목 테이블로 사용한다. 핵심 필드는 `id`, `parentId`(루트는 `NULL`), `title`, `content`, `archivedAt`, `createdAt`, `updatedAt`이다. 기존 주제 색상은 데이터 손실을 막기 위해 선택적 `accentColor`로 옮기되, 초기 화면에서는 루트 문서에만 표시한다. 직접 하위 문서는 기존과 같이 최근 수정순으로 보여주고, 수동 순서 지정은 후속 단계로 둔다.

참조는 별도 `document_references` 테이블에 `sourceDocumentId`, `targetDocumentId`, `createdAt`으로 저장한다. 두 ID는 문서 외래 키이며, `(sourceDocumentId, targetDocumentId)`는 유일하다. 역참조 목록을 위해 `targetDocumentId`에도 인덱스를 둔다. 본문 텍스트와 참조 관계는 서로 독립적이다.

- 문서 ID는 부모나 위치와 무관하게 유지된다. 이동해도 본문과 하위 문서의 ID는 그대로다.
- 부모는 반드시 존재하고 활성 상태여야 하며, 자기 자신이나 자기 하위 문서를 부모로 지정할 수 없다. 모든 포함 관계는 순환이 없는 트리여야 한다. 보관된 조상 아래로도 이동할 수 없다.
- 동일 제목은 허용한다. 식별과 URL은 제목이 아닌 ID를 쓴다.
- 이동은 문서와 그 하위 트리를 함께 옮기는 것과 같다. 하위 문서의 `parentId`는 변경하지 않는다.
- 같은 문서를 둘 이상의 부모 밑에 두지 않는다. 여러 문서에서 다시 가리키고 싶다면 참조를 쓴다.
- 자기 자신을 참조하는 관계와 중복 참조는 허용하지 않는다. 서로 다른 두 문서가 상호 참조하는 것은 허용한다. 참조 그래프에는 포함 트리와 달리 순환 제한이 없다.
- 문서를 이동해도 참조·역참조는 유지된다. 참조가 연결된 문서의 제목이 바뀌면 목록에는 새 제목이 표시된다.
- 루트 카드의 `문서 수`는 자신을 제외한 활성 하위 문서의 총수로 정의한다. 최근 활동은 루트와 표시 가능한 하위 문서의 최신 수정 시각이다. 직접 자식 수와 전체 하위 문서 수는 화면에서 구분해 표기한다.
- 모든 쓰기 작업은 서버에서 ID·입력값·부모 상태를 검증한다. 이동 시 순환 검사는 같은 트랜잭션 안에서 수행하고 동시 이동에도 순환이 생기지 않도록 관계 변경을 직렬화한다.

## 보관과 표시

문서 보관은 그 문서의 `archivedAt`만 설정한다. 자손의 값은 바꾸지 않는다. 보관된 문서 아래의 자손은 활성 탐색과 집계에서 함께 숨겨진다. 부모를 복원하면 개별적으로 보관되지 않은 자손이 다시 보인다. 개별적으로 보관된 자손은 계속 보관 상태다.

보관함에는 직접 보관한 문서를 원래 위치의 경로와 함께 보여준다. 보관된 부모 때문에 숨겨진 자손을 별도 보관 문서로 중복 표시하지 않는다. 보관된 부모 아래에 있는 문서의 편집·이동은 부모를 복원한 뒤 허용한다. 영구 삭제와 보관 시 자동 이동은 제공하지 않는다.

보관하거나 복원해도 참조 관계는 삭제·생성하지 않는다. 참조 또는 역참조의 상대 문서가 직접 보관됐거나 보관된 조상 아래에 있으면 목록에 `보관됨`으로 표시하고 읽기 전용 문서 화면으로 연결한다. 활성 문서 수·최근 활동 집계에는 이런 문서를 포함하지 않는다.

## 기존 데이터 전환

1. 기존 `topics`의 각 행을 루트 문서로 만든다. 이름은 제목, 설명은 본문, 색상은 `accentColor`, 보관·생성·수정 시각은 대응 필드로 옮긴다.
2. 기존 `documents`는 ID·본문·보관 상태를 보존하고, 소속 주제에서 변환된 루트 문서를 `parentId`로 지정한다. 기존 데이터에는 참조 관계가 없으므로 참조 테이블은 빈 상태에서 시작한다.
3. 전환 중에는 기존 주제 ID와 새 루트 문서 ID의 대응을 남겨 기존 `/topics/:topicId` 주소를 새 문서 주소로 안내한다. 문서 상세 주소는 문서 ID만으로 구성해 이동해도 유지한다.
4. 전환 전후 문서·주제 건수, 부모 연결, 보관 상태를 대조한다. 누락·고아 문서·순환이 없음을 확인한 뒤 구형 `topicId` 의존성을 제거한다. 운영 데이터에는 되돌릴 수 있는 백업과 별도 마이그레이션 절차를 마련한다.

### 준비 마이그레이션의 경계

`0003_puzzling_ricochet`은 최종 화면 전환에 앞선 **추가형 마이그레이션**이다. `documents.parent_id`, `accent_color`, 옛 주제 ID와 새 루트 ID를 잇는 `legacy_topic_id`, 별도 `document_references`를 추가한다. 기존 `topics`와 `documents.topic_id`는 이 단계에서 제거하지 않는다. 주제마다 새 루트 문서를 만들고 기존 문서의 ID를 유지한 채 부모를 그 루트로 지정한다.

전환 기간에 기존 화면에서 주제를 생성·수정·보관하면 DB 트리거가 대응하는 루트 문서를 같은 쓰기 작업 안에서 갱신한다. 기존 화면에서 새 문서를 만들면 다른 트리거가 부모 루트를 붙인다. 따라서 준비 마이그레이션 이후에도 현재 화면의 쓰기가 새 계층에서 빠지지 않는다. 새 문서 화면으로 완전히 전환할 때는 옛 주제 쓰기를 중단하고 이 동기화 트리거를 제거해야 한다. 그 뒤 `topic_id`와 구형 주제 테이블을 정리한다.

현재 Neon HTTP 드라이버는 대화형 트랜잭션을 지원하지 않는다. 이후 문서 이동의 부모·조상 검증과 변경은 별도 DB 함수에서 한 트랜잭션으로 처리하고, 동시 이동은 트랜잭션 수준 잠금으로 직렬화한다. 현재 준비 마이그레이션의 DB 제약은 부모 존재, 직접 자기 포함, 참조 중복·자기 참조를 막는다. **간접 순환과 보관된 조상 아래로의 이동은 아직 새 쓰기 기능이 없으므로, 다음 단계에서 DB 함수와 함께 검증한다.**

운영 DB 적용 시에는 먼저 백업과 쓰기 중단 구간을 준비하고 마이그레이션을 적용한다. 적용 후 주제 수와 `legacy_topic_id`가 있는 루트 수, 기존 문서의 부모 연결, 보관·본문·시각을 대조한 다음 새 코드를 배포한다. 이 저장소에서는 연결 정보가 없어 운영 DB에 마이그레이션을 실행하지 않았다.

## 구현 순서와 완료 기준

1. **데이터 전환**: 스키마와 마이그레이션, 부모 관계 검증 및 데이터 보존 검사를 추가한다.
2. **문서 읽기**: 루트 목록, 문서 상세, 경로, 직접 자식 목록, 하위 문서 집계를 제공한다.
3. **문서 쓰기**: 루트/하위 문서 생성, 수정, 이동, 보관·복원을 연결한다. 잘못된 부모와 순환 이동은 거절한다.
4. **참조·역참조**: 제목 검색으로 참조를 추가·제거하고, 문서 상세에서 양방향 목록과 보관 상태를 확인한다.
5. **화면 정리**: 기존 주제 중심 문구와 경로를 문서 중심으로 바꾸고, 옛 주소를 연결한다.

완료로 보려면 기존 모든 주제와 문서가 전환 후에도 열려야 한다. 세 단계 이상의 문서를 만들고, 중간 문서를 통째로 옮기고, 순환 이동을 차단할 수 있어야 한다. 한 문서를 서로 다른 두 문서에서 참조하면 대상의 역참조에 두 문서가 모두 나타나야 한다. 참조된 문서를 옮기거나 보관·복원해도 참조가 유지되어야 한다. 부모 보관·복원 후 자손의 표시가 위 규칙과 일치해야 하며, Todo 동작은 유지되어야 한다.

## 후속 범위

여러 부모에 같은 문서를 포함하는 관계, 본문 안의 문서 삽입·자동 참조 추출, 전문 검색, 그래프 뷰, 권한 공유는 이번 변경에 포함하지 않는다. 여러 부모가 필요해지면 단일 `parentId` 대신 별도 포함 관계 테이블과 순환 검사로 모델을 바꿔야 한다.
